# パーソナル統合カレンダーアプリ 要件定義書

## 1. 概要

日々の「予定」「todo」「日記」「家計簿」をひとつのカレンダー上でまとめて記録・確認できる、個人利用向けのAndroidアプリ。
複数のアプリを使い分ける手間をなくし、カレンダーの日付を起点にその日の出来事・やることお金の動きを一元管理することを目的とする。

## 2. 想定ユーザー

- 開発者本人（作者）による個人利用を第一の目的とする。
- 将来的な一般公開は現時点では未定（要件・実装が固まった段階で改めて検討）。

## 3. コンセプト

- **カレンダーが起点**：月表示のカレンダーで日付をタップすると、その日の「予定」「todo」「日記」「家計簿」をまとめて確認・入力できる（日付タップ型のUI）。
- **1画面で完結**：日付ごとの詳細画面で4つの情報を横断的に見られるようにし、記録の手間を最小限にする。
- **軽量な日記**：長文ではなく、数行程度のライトな記録を想定（一言日記・ひとことメモに近い運用）。
- **どこからでもクイック入力**：カレンダーで日付を選んでから入力する通常の流れに加え、ホーム画面から1〜2タップで「予定」「todo」「日記」「家計簿」をすぐに記録できるクイック入力の導線を用意し、記録のハードルを下げる。

## 4. 主要機能

### 4.1 予定管理
- 日付・時刻（任意）・タイトル・メモを持つ予定を登録できる。
- 1日に複数件登録可能。
- カレンダーの月表示で、予定がある日が一目でわかる（インジケーター表示）。
- **繰り返し予定**：毎週・毎月などの間隔で繰り返す予定にMVPから対応する。繰り返しルールは「毎週◯曜日」「毎月◯日」程度のシンプルなパターンに限定し、1回分だけの例外編集・除外といった細かい制御は将来拡張とする。
- **クイック入力**：ホーム画面のクイック追加から「予定」を選ぶと、日付はデフォルトで当日が入った状態で、タイトルだけ入力すればすぐに登録できる最小入力フォームを開く（日時変更は任意で可能）。

### 4.2 Todo管理
- タイトル・期日（任意）・完了状態を持つtodoを登録できる。
- 期日なしのtodo（いつかやる、を含む）にも対応。
- 完了/未完了の切り替え、未完了のみの一覧表示。
- 期日超過（期限切れ未完了）のtodoが分かるようにする。
- **優先度は持たせない**：シンプルさを優先し、タイトルと期日のみで管理する（並び順は期日順、期日なしは末尾）。
- **クイック入力**：ホーム画面のクイック追加から「todo」を選ぶと、タイトルのみ入力してそのまま保存できる（期日は未設定のまま登録し、後から設定も可能）。

### 4.3 日記
- 1日1件、数行程度のテキストを記録する（簡易な日記帳）。
- 過去の日記を日付から遡って参照できる。
- 文字数の目安は200文字程度とし、UI上は数行分のテキストエリアで表示する。超過時もエラーにはせず入力を許容する（ソフトな目安であり、厳密な文字数制限はMVPでは設けない）。
- **クイック入力**：ホーム画面のクイック追加から「日記」を選ぶと、当日分の日記入力欄に直接遷移し、数行書いてすぐに保存できる（当日分が既にある場合は追記・編集として開く）。

### 4.4 家計簿
- 収入・支出を、日付・金額・カテゴリ・メモ付きで記録できる。
- 金額は**日本円・整数（円単位）**で扱う（小数は扱わない）。
- **初期カテゴリ（費目）**：以下を初期データとして登録し、クイック入力ボタンの初期候補とする。ユーザーは「設定」からカテゴリの追加・編集・並び替えが可能。
  - 支出：外食、アミューズメント、カフェ、コーヒー豆、食材
  - 収入：給与
- **月別の収支合計をグラフ・サマリーで表示**（棒グラフ／円グラフ等でカテゴリ内訳も確認できるようにする）。
- **クイック入力（費目ボタン）**：ホーム画面のクイック追加から「家計簿」を選ぶと、上記の費目がボタン／アイコンとして並んだ画面が開き、タップすると当該カテゴリ・当日日付が選択された状態で金額入力に直接遷移できる（カテゴリ選択の手間を省く）。
  - どの費目をボタン化するかはユーザーが「設定」から選択・並び替えできるようにする（お気に入り／よく使う費目の登録）。
  - ボタンからの入力は「日付・カテゴリ済み → 金額のみ入力してそのまま保存」という最短フローとする。
- 予算設定・予算対実績の管理は将来拡張とする（MVPスコープ外）。

## 5. 画面構成（案）

日付タップ型を採用し、カレンダーをアプリのホームとする。週の始まりは**日曜始まり**とする。

```
[ボトムナビゲーション]
 ├─ カレンダー（ホーム）
 │    ├─ 月表示カレンダー（日曜始まり）
 │    │    └─ 日付タップ → 日別詳細画面
 │    │         ├─ その日の予定一覧（追加・編集・削除）
 │    │         ├─ その日のtodo一覧（追加・完了切替・削除）
 │    │         ├─ その日の日記（数行入力・編集）
 │    │         └─ その日の家計簿明細（追加・編集・削除）
 │    │              └─ よく使う費目ボタン／アイコンをタップ → 金額入力画面へ直行
 │    └─ クイック追加FAB（フローティングボタン）
 │         └─ タップで種別選択（予定／todo／日記／家計簿）
 │              ├─ 予定 → タイトルのみで登録できる最小入力（日付は当日デフォルト）
 │              ├─ todo → タイトルのみで登録できる最小入力（期日は任意）
 │              ├─ 日記 → 当日分の日記入力欄に直接遷移
 │              └─ 家計簿 → よく使う費目ボタン一覧 → タップで金額入力へ
 ├─ Todo一覧
 │    └─ 全期間のtodoを横断的に表示（未完了優先、期限切れ強調）
 ├─ 家計簿サマリー
 │    └─ 月別収支グラフ、カテゴリ別内訳
 └─ 設定
      └─ カテゴリ管理、クイック追加のカスタマイズ、バックアップ/同期設定 など
```

- クイック追加FABは、カレンダーを日付タップで操作する通常の流れをスキップし、「今すぐ・とにかく早く記録したい」場面（外出先での支出記録、思いついたtodoの追加など）に対応するための入口と位置づける。
- 月表示カレンダーの各日付セルには、その日に記録がある種別を色分けしたインジケーター（ドット）で表示する。
  - 予定：青
  - todo：オレンジ
  - 日記：緑
  - 家計簿：赤（支出）／紫（収入）
  - 1日に複数種別の記録がある場合は、該当する色のドットを並べて表示する。

## 6. 対象端末・画面サイズ

- **想定端末**：Galaxy A25 5G を基準デバイスとする。
  - ディスプレイ：約6.5インチ Super AMOLED
  - 解像度：1080 × 2340（FHD+）
  - アスペクト比：約19.5:9
  - 画面密度：xxhdpi 相当（約390〜400dpi）
- レイアウトはdp単位を基準に設計し、Galaxy A25 5Gの画面で違和感なく使えることを主要な確認基準とする。
- 個人利用アプリのため多機種対応の優先度は低いが、Jetpack Composeの標準的なレスポンシブ対応（可変サイズのレイアウトコンポーネント使用など）は踏襲し、極端な崩れが起きない範囲は担保する。
- 実機／エミュレータでの動作確認は、Galaxy A25 5G相当の解像度・画面サイズ（1080×2340, ~6.5インチ）のエミュレータプロファイルを基本とする。

## 7. データモデル（ドラフト）

| エンティティ | 主な項目 |
|---|---|
| Event（予定） | id, date, startTime, endTime（任意）, title, memo, repeatRule（NONE/WEEKLY/MONTHLY）, repeatUntil（任意） |
| Todo | id, dueDate（任意）, title, memo, isDone, completedAt |
| DiaryEntry（日記） | id, date（1日1件）, content |
| Transaction（家計簿明細） | id, date, type（収入/支出）, amount（Int, 円単位）, categoryId, memo |
| Category（家計簿カテゴリ） | id, name, type（収入/支出）, isQuickAccess（クイック入力ボタン表示対象か）, sortOrder, color/icon |

- 予定・todo・日記・家計簿はいずれも `date` を持ち、カレンダーの日付と紐づく。
- todoの `dueDate` は任意（未設定＝「いつかやる」リストに入る）。
- Categoryの初期データ（シード）：
  - 支出：外食、アミューズメント、カフェ、コーヒー豆、食材
  - 収入：給与

## 8. 技術スタック・初期設定（案）

- **言語／UI**：Kotlin + Jetpack Compose（現行のAndroidネイティブ開発の標準構成）
- **アーキテクチャ**：MVVM（ViewModel + StateFlow）、Android推奨のアプリアーキテクチャに準拠
- **ローカルDB**：Room
- **非同期処理**：Kotlin Coroutines / Flow
- **グラフ表示**：Compose対応のチャートライブラリ（例：Vico）を採用予定
- **クラウド同期（将来）**：Firebase Authentication（Googleログイン）＋ Cloud Firestore による複数端末同期を検討
- **テーマ**：Material3のライト／ダークテーマに対応し、端末のシステム設定に追従する。
- **minSdkVersion**：26（Android 8.0）を目安とする。個人利用端末（Galaxy A25 5G、Android 14系）のみを想定するため、実装難易度に応じて引き上げても支障はない。
- **targetSdkVersion / compileSdkVersion**：開発時点の最新安定版を使用する。
- **applicationId（パッケージ名）**：`com.h31030.personalcalendar`（仮）。正式名称が決まり次第変更する。

## 9. データ保存方針

- **フェーズ1（MVP）**：端末内のRoomデータベースにローカル保存。外部サービス連携なしで単体動作。
- **フェーズ2**：Firebase等を用いたクラウド同期・複数端末間のバックアップ／リストアに対応（本人の利用端末が増えた場合や、万一の機種変更に備える）。
- クラウド同期を見据え、データモデルは同期しやすい形（各レコードに一意なID・更新日時を持たせる等）で最初から設計する。

## 10. スコープ

### MVP（フェーズ1）
- 日付タップ型のカレンダー画面（月表示・日曜始まり、当日ハイライト、色分けインジケーター）
- 予定・todo・日記・家計簿明細の基本CRUD（日別詳細画面から一括操作）
- 予定の繰り返し登録（毎週／毎月の単純なパターン）
- Todo一覧画面（未完了／期限切れの可視化、優先度なしのシンプル構成）
- 家計簿：初期カテゴリでのカテゴリ別入力、月別収支合計・グラフ表示、よく使う費目のクイック入力ボタン
- ホーム画面のクイック追加FAB（予定・todo・日記・家計簿すべてに対応した最小入力フロー）
- Galaxy A25 5G（約6.5インチ, 1080×2340）を基準にしたレイアウト、ライト／ダークテーマ対応
- ローカル保存のみ（Room）

### 将来拡張（フェーズ2以降）
- Firebaseによるクラウド同期・複数端末対応
- 予算設定・予算対実績管理
- 通知・リマインダー（todo期日、予定の事前通知）
- 繰り返し予定の例外編集（1回分だけの変更・削除など）
- データのエクスポート／インポート（CSV等）
- ウィジェット対応
- 一般公開を見据えたオンボーディング・アカウント管理
